## Credible question still open: equal pooling versus training-only learned pooling

The current mixture uses a constant50/50 split. The earlier results support component complementarity but do not establish50/50 as optimal. A distinct possible next contrast is a single convex component weight estimated using strictly chronological validation folds contained entirely inside each forecast's available training history. It must never read earlier benchmark/OOS losses, use asset/family outcome routes, or change the main evaluation score. The same fitted weight would govern complete paths; daily segment stitching is a different law and is not implied.

Academic support for considering this mechanism, not a claim it will win: [Yao, Vehtari, Simpson and Gelman,2018](https://sites.stat.columbia.edu/gelman/research/published/stacking.pdf) formulate predictive-distribution stacking using proper scoring rules, including CRPS. Their general leave-one-out procedure cannot simply be copied to dependent chronological returns. [Gneiting and Ranjan,2013](https://arxiv.org/abs/1106.1638) examine probabilistic pooling and its calibration/dispersion limitations, with an S&P500 return application. Neither establishes a win here.

Before any such field test: specify chronological folds, minimum fitting lengths, horizon coverage, exact1,000-path accounting, estimation uncertainty/overfitting and runtime cost; freeze one hypothesis, qualify it and use the same broad representative main-score gates. No learned-pooling implementation or new field admission is implied by this note. Review the GJR result first and target the actual current winner. This credible untested mechanism is one reason the wider search is not exhausted.
