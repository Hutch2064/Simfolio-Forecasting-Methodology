# Fast nested horizon selector: initial 19-option implementation

This is the first implementation, not the complete future component universe. It selects one coherent asset-level procedure for the requested maximum native horizon. The 19 options are the unchanged trained parent, both exact raw joint block baselines, and16pure filters (constant, revertingEWMA, GARCH, conditionalRMS latent volatility; Gaussian or joint historical residuals; sample or shrunk mean). All pure filters retain the existing correlated mean uncertainty. NoMCMC, no portfolio-level fit, no splicing unrelated selected daily forecasts.

At each outer request, complete nonoverlapping target-length validation blocks are taken backward from the end of the available training prefix. Training floor504is the existing panel minimum. Compare one or up to three recent complete blocks with32inner simulations; these are explicit computational budgets, not financial parameters or outcome-tuned cutoffs. Shared prefix fits avoid refitting each combination. The same history, portfolio weights and horizon drive the choice. Fit each inner origin without its validation observations, evaluate that inner future, then refit the selected method on all available current history. Stable bank order resolves exact ties. If no complete target-length block fits after504training rows, fall back exactly to the trained parent and disclose the reason. Do not extrapolate short-horizon validation as evidence for a longer horizon.

Inner selection minimizes ensembleCRPS scaled by training portfolioSD*sqrt(nativelead), with logarithmic native-lead mass across1..H. This is a native-time internal fitting criterion: it does not claim to reproduce the outer score's exact calendar spacing. The outer canonical calendar/family/class/quarter/two-branch main score is unchanged and is the only reported selection score for panel candidates. Neither outer realized returns nor cached outer scores are inputs to this selector. Portfolio accounting, final1000paths and full source/hash guards remain unchanged.

Initial causal/accounting qualification: eight tests, including independently rebuilt innerCRPS, exact selected-model output, prefix/weights/horizon identity, full-target block coverage, exact parent fallback and per-budget origin counts. Initial import setup error was before any scientific run and is preserved. First real-data screen: one horizon-eligible case per70families from the existing355case development plan, with unchanged parent and fixedreference checkpoints on identical1000path coverage. This eligibility-focused screen is not a replacement full panel, and excludes unsupported long horizons deliberately to test actual selection. Later validation must include fallback cases and separate reserved/broad tests. No independence or significance claim; samples are development data.

Runtime evidence is local numerical compute only. Record inner shared fitting, inner forecast/scoring, final refitting and outer1000path forecast/scoring separately. The1and3origin variants may share3origin computation in the batch; that pooled timing is not evidence for isolated1origin latency. No web latency or production-readiness claim.
